# Shared integration contracts

`src/lib/contracts/index.ts` is the source of truth. All network input and model output must pass its Zod schemas on the server. JSON uses camelCase; database adapters map snake_case explicitly. Dates use ISO `YYYY-MM-DD`; timestamps use UTC ISO datetime strings. Countries use the defined ASEAN ISO codes. Nullable profile fields mean unknown, never zero or an inferred value.

## Planned API surface

These endpoints describe the feature handoff; they are not implemented by the foundation.

| Endpoint | Input | Success | Access |
| --- | --- | --- | --- |
| `GET /api/startups/me` | Authenticated session | `{ data: StartupProfile }` | Owner only |
| `PUT /api/startups/me` | `startupProfileInputSchema` | `{ data: StartupProfile }` | Owner only |
| `GET /api/opportunities` | Validated search/filter query | `{ data: Opportunity[] }` | Published records only |
| `GET /api/opportunities/:id` | UUID | `{ data: Opportunity }` | Published records only |
| `POST /api/eligibility/compile` | Opportunity UUID | `{ data: CompiledRequirements }` | Authenticated; rate limited |
| `POST /api/eligibility/evaluate` | Opportunity UUID | `{ data: EligibilityEvaluation }` | Authenticated startup owner |

The server derives `ownerId` from a verified Supabase user; client requests cannot set ownership. Evaluation must load the user's startup and trusted server-stored compilation, rather than accepting either from arbitrary callers. Compilation is expensive: restrict and rate limit it, cache by source content hash/model/prompt version, and never let callers supply an arbitrary fetch URL (SSRF risk).

Errors follow `apiErrorSchema`: `{ error: { code, message, requestId? } }`. Use HTTP 400 for validation, 401 for missing authentication, 403 for forbidden access, 404 for absent records, 429 for rate limiting, 503 for missing AI configuration/upstream outages, and 500 for internal errors. Do not return provider payloads, tokens, stack traces, or sensitive profile information in errors.

## Rule compilation and evaluation

The AI extracts typed rules with a quote, source URL, locator, and retrieval timestamp for every requirement. Supported rules are country membership, startup stage membership, funding stage membership, maximum employees, and incorporation on or after a date. These rules form an AND conjunction. OR groups, sector interpretations, ownership, exceptions, conflicting sources, and ambiguous language become `unsupported` with an explanation; do not simplify them into definitive rules.

Validation proves JSON shape, not factual grounding. The future compiler must verify each quote occurs in the fetched source, retain the original source snapshot/hash, record model/prompt provenance, and mark extraction `partial` whenever coverage is uncertain. Source text is untrusted data, including any instructions embedded in documents. Never execute a generated expression or fetch a URL generated by the model. Bound input/output size, use request timeouts, handle invalid JSON and provider failures, and return a review state on uncertain extraction. PDF uploads are deferred; add size, MIME and signature checks before accepting them.

`evaluateEligibility` validates both inputs. Any supported failure yields `ineligible`; otherwise unknown data, unsupported requirements, empty rule sets, partial extraction, or warnings yield `needs_review`. Only complete, warning-free, all-pass results yield `potentially_eligible`. This is not an application approval. Deadlines and source freshness require separate validation before presenting a live recommendation.

## Open-weight AI contribution

The intended product builds on Qwen open weights to compile unstructured programme requirements into evidence-backed, validated rules. The surrounding TypeScript harness constrains the model's output and evaluates supported rules deterministically. Hosted OpenAI-compatible inference is an interface choice; it does not establish that the selected model has open weights.

The foundation provides server-only `getAiConfig()` using `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL`; it deliberately makes no provider call. The AI engineer must select an available Qwen model, verify its published weight repository and model-specific license, and record the exact provider model ID, upstream weights/revision, license, prompt version, and limitations in the README. Do not silently switch to a proprietary model or claim a real AI demo before integration and end-to-end testing. Credentials stay server-side and are configured directly in deployment settings.

`mockStartup`, `mockOpportunities`, and `mockCompilation` are explicitly fictional fixtures with reserved example.com URLs. No model was invoked to create their compilation. They unblock interface and contract development; they must never appear as verified real programmes.
